# Локальный живой перевод звонков

Перевод запускается в веб-клиенте и Windows WebView2, на устройствах участников. На API, LiveKit и сервере с 2 ядрами / 4 ГБ ОЗУ модели не загружаются и не выполняются. Сервер по-прежнему передаёт зашифрованное медиа и небольшие зашифрованные пакеты субтитров. Это не устраняет обычные затраты сервера на звонки и сетевой трафик.

## Как включить

1. Обновить клиент из ветки `Gleb_test`, подключиться к обычному или групповому звонку.
2. В панели «Живой перевод» выбрать язык субтитров и нажать «Включить перевод».
3. Каждый участник, чью речь нужно переводить, отдельно включает «Распознавать и передавать мою речь участникам» и указывает язык своей речи. По умолчанию микрофон для перевода не обрабатывается.
4. При наличии установленного локального системного голоса можно включить озвучивание. Облачные голоса и удалённое распознавание не используются. При выключении звука звонка озвучивание прекращается. На время чтения микрофон перевода приостанавливается, чтобы голос не попал обратно в распознавание.

Участник может выбрать только приём субтитров, не запуская Whisper. Самый лёгкий вариант — приём английских субтитров: ему не нужны нейросетевые модели. Приём русских, немецких, французских или испанских субтитров требует одну модель перевода текста. Для речи участника, который не включил распознавание у себя, субтитров нет: чужие аудиопотоки на устройстве слушателя не распознаются.

## Как распределяется работа

`свой микрофон → Whisper Tiny → английский текст → зашифрованные пакеты LiveKit → одна Marian-модель выбранного языка → субтитры / локальный голос`

Каждый говорящий распознаёт только собственный микрофон один раз независимо от числа слушателей. Whisper для английской речи использует `transcribe`, для остальных поддерживаемых языков — `translate` в английский. У слушателя одна модель `en → выбранный язык`, даже если в группе говорят на разных языках. Английский промежуточный текст позволяет не держать отдельные модели для каждой пары языков. Обратная сторона — возможная потеря смысла при двух последовательных переводах; исходный текст речи отдельно не распознаётся.

Доступны русский, английский, немецкий, французский, испанский. Используется `@huggingface/transformers@3.8.1`, квантование `q8`, ONNX WASM в отдельном Worker, один поток и последовательное выполнение распознавания / перевода. GPU, SharedArrayBuffer и заголовки cross-origin isolation не требуются.

## Загрузка и память

Веса скачиваются непосредственно браузером с Hugging Face после включения соответствующей функции. Веса не попадают в `dist`, Docker-образ, API или LiveKit. В приложении лежит только код среды ONNX Runtime: примерно 21,6 МБ WASM до сжатия, загружаемый при запуске модели. Поддерживающий JS-модуль поставляется с того же домена, поэтому разрешение внешних скриптов в CSP не требуется.

Примерные размеры **только квантованных весов**, без метаданных и токенизаторов:

| Режим / модель | Веса |
| --- | ---: |
| Только английские входящие субтитры | 0 МБ |
| Whisper Tiny, если включена своя речь | 40,9 МБ |
| Marian en → ru | 110,6 МБ |
| Marian en → de | 106,0 МБ |
| Marian en → fr | 107,5 МБ |
| Marian en → es | 113,1 МБ |

Размер скачивания не равен потреблению ОЗУ: графы, тензоры и рабочая память требуют дополнительную память. Минимальные требования и скорость на слабых устройствах пока не установлены. Кэш браузера позволяет повторно использовать скачанное, но может быть очищен браузером, закрытым режимом или нехваткой места. Изменение языка перезапускает Worker; старые модели освобождаются, а новая пара загружается по необходимости. Прерывание перевода завершает Worker, включая выполняющуюся загрузку / вычисление. Уже скачанные файлы могут остаться в браузерном кэше.

## Задержка и ограничение нагрузки

Это перевод коротких фраз с задержкой, а не синхронное пословное озвучивание. Захват пропускает тишину, завершает фразу после 600 мс паузы и ограничивает непрерывный фрагмент шестью секундами. На распознавание подаётся моно PCM 16 кГц; частота устройства преобразуется потоково, включая 44,1 кГц.

В ожидании остаются максимум один аудиофрагмент и шесть текстовых фрагментов; старая работа отбрасывается. Нельзя получить очередь в несколько минут. При перегрузке появляются счётчик пропусков и подсказка отключить распознавание своей речи. Отдельный расчёт ограничен 30 секундами, загрузка — пятью минутами. Ошибка перевода останавливает только перевод; обычный звонок продолжается. Кнопка повтора запускает новую сессию.

Гарантировать обработку речи в реальном времени на любом слабом устройстве нельзя. Для такого устройства сначала проверить приём субтитров, затем отдельно включить свою речь. Если появляются пропуски, отключить свою речь, перейти на английские субтитры или использовать более мощное устройство. Маленькая модель ошибается на шуме, тихой речи, именах и при одновременной речи; простое выделение речи по энергии не гарантирует отсутствие ложных срабатываний.

## Приватность и шифрование

Сырые фрагменты микрофона для ИИ не отправляются на сервер или поставщику модели. Обычная передача микрофона в звонке остаётся частью звонка. Веса скачиваются с Hugging Face: этот сервис получает обычные сведения о запросе загрузки, но не содержимое речи.

Субтитры передаются только текущим участникам через `coherent.translation.v1`; в базе сообщений, localStorage и логах они не сохраняются. В интерфейсе хранится восемь последних фраз. `livekit-client@2.17.2` с опцией `RoomOptions.encryption` шифрует также data packets. Приём проверяет тип GCM, подключение, проверенного SDK-отправителя, комнату, версию, язык, длину, частоту и повторные идентификаторы. Plaintext-пакеты отбрасываются. Ограничение — шесть фрагментов за десять секунд на участника, до 600 символов / 4096 байт на пакет. [Шифрование LiveKit](https://docs.livekit.io/transport/encryption/).

При выключении микрофона захват для перевода закрывается, ожидающее аудио и результат старого расчёта отбрасываются. При выходе, отключении функции, смене комнаты или языков освобождаются Worker, AudioContext и подписки. Сам микрофон звонка принадлежит звонку и этой функцией не останавливается.

## Проверка

Автоматически: `cd frontend && npm ci && npm test && npm run build`. Тесты проверяют ограничение очереди, ресэмплинг, тишину и границы фраз, сброс при mute, отбрасывание старых результатов, таймауты, очистку ресурсов, режим без моделей, сериализацию Worker и защиту транспорта. Сборка проверяет TypeScript и выдаёт среду WASM отдельными ресурсами без `.onnx`.

Проверка этой реализации: 80 тестов в 16 файлах проходят, TypeScript и production-сборка проходят. В браузере с CSP из production успешно запущены настоящие q8 WASM-модели: английский текст переведён в «Привет, как дела?» за 398 мс, шесть секунд публичного тестового аудио распознаны за 2871 мс. Первая инициализация обеих моделей с загрузкой заняла 44,8 секунды. Это единичный тест на компьютере разработчика, не измерение слабого устройства и не проверка многопользовательского звонка. Полная проверка звонка и Windows WebView2 остаётся частью приёмки.

Для приёмки нужны реальные браузеры / WebView2 и звонок минимум трёх устройств: русский говорящий, английский говорящий, слабый слушатель. Проверить качество речи, холодную / повторную загрузку, стабильность звука звонка, задержку и память, отключение микрофона во время расчёта, переподключение, выход и озвучивание. В Network не должно быть запросов загрузки весов к API или отправки PCM в сервис распознавания. Значения времени и памяти для целевых устройств нужно записать перед обещаниями о производительности.

- [Xenova/opus-mt-en-ru](https://huggingface.co/Xenova/opus-mt-en-ru), [en-fr](https://huggingface.co/Xenova/opus-mt-en-fr), [en-es](https://huggingface.co/Xenova/opus-mt-en-es): Marian / OPUS-MT, Apache-2.0.
- [Helsinki-NLP/opus-mt-en-de](https://huggingface.co/Helsinki-NLP/opus-mt-en-de), CC-BY-4.0; ONNX-конверсия [Xenova/opus-mt-en-de](https://huggingface.co/Xenova/opus-mt-en-de). Авторы: Helsinki-NLP / OPUS-MT; используется квантованная ONNX-конверсия для локального вывода.
