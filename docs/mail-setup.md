# Почта подтверждений на одном VPS

На VPS установлен Postfix и OpenDKIM. SMTP принимает сообщения только с localhost и из сети контейнеров Coherent; публичного входящего SMTP нет. Ключ DKIM находится в `/etc/opendkim/keys/coherent-web.ru/coherent2026.private`, публичная запись — в [mail-dkim.txt](mail-dkim.txt).

Для отправки от `noreply@coherent-web.ru` добавить в DNS домена:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `mail` | `31.76.77.197` |
| TXT | `@` | `v=spf1 ip4:31.76.77.197 -all` |
| TXT | `coherent2026._domainkey` | Объединённое значение строк в кавычках из `mail-dkim.txt`, без скобок и комментария |
| TXT | `_dmarc` | `v=DMARC1; p=none; adkim=s; aspf=s` |

В панели провайдера VPS установить **PTR для 31.76.77.197 → mail.coherent-web.ru**. Это отдельная настройка обратного DNS, она не задаётся обычной TXT-записью. На 25 октября 2026 записи выше опубликованы и проверены. При добавлении других отправителей нужно объединить разрешения в одной SPF-записи, не создавать вторую.

Эта конфигурация предназначена для исходящих кодов, почтовые ящики и входящая почта не реализованы. MX существующего домена менять не требуется. Проверены DNS, ключ DKIM и подпись реального сообщения в локальной очереди. Gmail принял проверочное письмо владельцу, но поместил его в спам; доставка во входящие пока не подтверждена. Без заголовков Gmail точную причину фильтрации установить нельзя.

После успешной проверки доставки в `deploy/.env`:

```dotenv
SMTP_HOST=host.docker.internal
SMTP_PORT=25
SMTP_STARTTLS=false
SMTP_USERNAME=
SMTP_PASSWORD=
SMTP_FROM=noreply@coherent-web.ru
```

Соединение приложения с почтовым сервисом идёт по закрытой сети Docker. Исходящая доставка Postfix к получателю требует TLS. Коды не журналируются приложением и хранятся в БД только как HMAC, действуют 10 минут, имеют пять попыток проверки, ограничение повторной отправки и привязку к версии сессии. Привязка адреса требует текущий пароль. SMTP выключен в конфигурации приложения до проверки домена и доставки.

Повторяемая настройка VPS: `deploy/setup-mail.sh`. Скрипт добавляет узкое правило UFW: SMTP разрешён только с моста и подсети `coherent_default` на внутренний адрес хоста. При пересоздании сети Docker или изменении её подсети нужно повторить настройку доверенных сетей и правила UFW. Основные источники: [Postfix: relay control](https://www.postfix.org/SMTPD_ACCESS_README.html), [Postfix: basic configuration](https://www.postfix.org/BASIC_CONFIGURATION_README.html), [OpenDKIM в Debian](https://wiki.debian.org/opendkim).
