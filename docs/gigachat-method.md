# Отдельный метод перевода через GigaChat

Метод предназначен для текста коротких реплик звонка. API Coherent не загружает и не запускает Whisper, Silero, Marian или Piper. Захват/распознавание и синтез остаются на устройствах участников; VPS с 2 CPU / 4 ГБ только проверяет доступ, ограничивает запросы и обращается к внешнему GigaChat API.

В звонке открой «Живой перевод» → «Способ перевода, языки и озвучивание» и выбери «GigaChat API + Silero + языковые аудиоканалы». Поле «Я говорю на» задаёт язык распознавания твоего микрофона. Поле «Слушаю перевод на» выбирает язык входящих фраз. Для озвучивания хотя бы один слушатель на каждом языке разрешает своему устройству вести канал.

**Распознанный текст разрешённых фраз передаётся серверу Coherent и GigaChat.** Запрос к GigaChat содержит текст и два языка. Аудио звонка и переведённые аудиодорожки передаются участникам с шифрованием LiveKit. Ключ авторизации GigaChat хранится в окружении API Coherent.

Говорящий отдельно разрешает внешний перевод своей речи; клиент передаёт `cloudAllowed` внутри аутентифицированного пакета субтитров. Обычный клиент не отправляет чужую фразу в GigaChat без этого разрешения. У старых/локальных пакетов разрешение отсутствует и считается выключенным. Сервер не получает MLS-ключи и не может независимо проверить этот флаг исходного шифротекста; это не обещание криптографически запретить недобросовестному получателю копировать уже доступный ему текст в сторонние сервисы.

## Настройка владельцем API

По умолчанию `GIGACHAT_ENABLED=false`. Не помещать ключи в Git или `VITE_*`.

```dotenv
GIGACHAT_ENABLED=true
GIGACHAT_AUTH_KEY=<ключ авторизации из своего проекта>
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2
GIGACHAT_BASE_URL=https://api.giga.chat/v1
GIGACHAT_CA_BUNDLE=/run/coherent-keys/gigachat-ca.pem
GIGACHAT_MAX_CONCURRENCY=1
GIGACHAT_TIMEOUT_SECONDS=15
```

`GIGACHAT_AUTH_KEY` — готовый ключ авторизации Basic, а не временный access token. Scope выбрать по аккаунту: `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. Модель `GigaChat-2` — документированный ID Lite; доступность выбранной модели зависит от проекта и баланса. Новые подключения/оплата могут оформляться через cloud.ru; данный адаптер реализует именно OAuth GigaChat, а не произвольный Cloud.ru API-key endpoint. [Авторизация](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api), [выбор модели](https://developers.sber.ru/docs/ru/gigachat/guides/selecting-a-model).

Новый основной base URL с июля 2026 — `https://api.giga.chat/v1`. Прежний официальный `https://gigachat.devices.sberbank.ru/api/v1` допускается для существующих подключений. Произвольный upstream URL запрещён настройками, браузер его не выбирает.

## Сертификаты и сеть

Проверка TLS всегда включена. Если стандартное доверенное хранилище не содержит нужный CA НУЦ Минцифры, владелец получает и проверяет сертификат штатным способом и указывает PEM bundle через `GIGACHAT_CA_BUNDLE`. Это путь **в контейнере**, файл должен быть смонтирован read-only. В production Compose уже есть read-only каталог `/etc/coherent/keys` → `/run/coherent-keys`; дополнительный публичный CA можно положить туда отдельно от приватных ключей. Не применять `verify_ssl_certs=False`, `curl -k` или глобальное отключение проверки TLS. [Официальное описание CA](https://developers.sber.ru/docs/ru/gigachat/certificates).

В текущем `deploy/staging/compose.yaml` API находится только во внутренней сети `app` с `internal: true`. Поэтому одних переменных GigaChat для этого стенда недостаточно: владельцу нужно отдельно подготовить проверенный ограниченный исходящий доступ к OAuth и API GigaChat и readonly CA при необходимости. Эта реализация не снимает сетевую изоляцию и не добавляет публичные порты автоматически. У пользователя был доступ только к Git, поэтому реальная конфигурация VPS и внешний вызов без ключа не проверены.

## API и ограничения

- `GET /api/v1/calls/{call_id}/translation/config` возвращает только `{enabled, configured, model}`, без ключей и токенов.
- `POST /api/v1/calls/{call_id}/translation` принимает `{text, source_language, target_language, segment_id, speaker_id}` и возвращает `{text}`.
- `segment_id` и `speaker_id` — UUID исходной фразы и SDK-идентификатора говорящего. Языки: `ru/en/de/fr/es`, входной/выходной текст до 600 символов, запрещены управляющие символы и лишние поля.
- Оба endpoint требуют авторизованного участника активного, не истёкшего звонка в той самой сессии, которая присоединилась к звонку. POST сохраняет обычную CSRF-защиту. Говорящий также должен участвовать в этом звонке.
- Исходный текст не записывается в БД или логи. Переведённый текст находится только в ограниченном кэше процесса до 30 секунд, максимум 128 записей. Ключ включает звонок, автора, сегмент, направление и SHA-256 текста; смена текста при том же ID не подменяет кэш.
- Одновременные слушатели одной фразы/языка используют один provider-запрос. Кэш/ожидающий результат проверяются до лимита новых задач, поэтому 100 слушателей не создают 100 платных обращений.
- Не более 16 разных выполняющихся/ожидающих задач на процесс; не более 24 новых задач за 10 секунд на участника в звонке. По умолчанию один upstream-запрос одновременно. Весь бюджет, включая очередь и OAuth, — 15 секунд, настраиваемый в пределах 2–20 секунд. Перегрузка возвращает 429, старые фразы не образуют неограниченную очередь.
- Access token кэшируется в памяти с запасом до срока истечения и обновляется совместно для параллельных запросов. После upstream 401 разрешена ровно одна повторная авторизация. Сетевые/платёжные ошибки автоматически многократно не повторяются, чтобы не накапливать старый перевод и платные вызовы.
- JSON-схема ограничивает ответ полем `text`; дополнительно проверяются формат, длина и завершение генерации. Обрезанный, отказной или повреждённый ответ не озвучивается. [Структурированный вывод](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output).

Кэш и concurrency общие только внутри одного процесса API. Для нескольких API workers потребуется общий механизм координации; текущий проект и без этого имеет ограничения многопроцессной доставки событий. Успешный тест со 100 одновременными читателями кэша не является нагрузочной приёмкой конференции на 100 участников: текущий сервер звонков ограничивает звонок десятью участниками, а квоты внешнего провайдера проверяются отдельно.

Для каждого языка участники выбирают координатора из устройств, которые разрешили озвучивание этого языка. Координатор загружает Piper, синтезирует перевод и публикует одну зашифрованную дорожку. Слушатели подписываются на дорожку выбранного языка. Если координатор выходит или у него не загружается голос, роль может перейти другому подходящему участнику. Без доступного координатора остаются субтитры. Для сохранения обычного звука звонка и снижения перекрытия оригинал приглушается только во время воспроизведения перевода.

## Ошибки и проверка

Недоступный метод/ключ, access/scope, баланс и неизвестная модель возвращают понятные ошибки без upstream body. 429 означает лимит, 504 — превышение общего времени, 502 — сетевой/повреждённый ответ. Ошибка CA требует настройки владельцем, а не отключения проверки. [Коды GigaChat](https://developers.sber.ru/docs/ru/gigachat/api/errors-description).

`backend/tests/test_call_translation.py` проверяет авторизацию/членство/владение сессией/CSRF, настройки без утечки ключа, входные лимиты, одиночный запрос для 100 слушателей, безопасную отмену, кэш/лимиты очереди, OAuth и sanitization ошибок. Реальных ключей в тестах нет, внешние вызовы подменены. Проверка настоящего ключа, CA, квоты, задержки и облачного качества остаётся обязательной на настроенном стенде.
