# Coherent: архитектура и ограничения

## Компоненты

```text
Браузер
├── React + TypeScript: интерфейс, каналы, чат и управление звонком
├── HTTPS / WebSocket ───────────────► Nginx ──► Uvicorn / FastAPI
└── WebRTC audio/video/screen ───────► LiveKit SFU
                                        │
                                        └── маршрутизация потоков участников

FastAPI ── SQLAlchemy ──► PostgreSQL
FastAPI ── выдаёт короткоживущий токен ──► Браузер подключается к LiveKit
Nginx ── TLS и HTTP/WebSocket-маршрутизация ──► FastAPI
```

Клиент никогда не получает постоянный секрет LiveKit. FastAPI проверяет права участника и выдаёт ему ограниченный по времени токен для конкретной комнаты.

Текстовый чат, статусы участников и события звонков идут через WebSocket FastAPI. Для запуска приложения используем Uvicorn — ASGI-сервер; Nginx останется внешним reverse proxy.

Сейчас реализованы личные текстовые беседы и первый срез личных звонков. Новые сообщения и состояния вызовов передаются через WebSocket подключённым пользователям в одном процессе API; клиент также периодически обновляет данные. Перед запуском нескольких процессов API понадобится общий канал событий, например Redis Pub/Sub, чтобы доставка между процессами оставалась мгновенной.

## Почему медиа отделено от FastAPI

Голос, камера и экран используют WebRTC, а не обычные HTTP-запросы. LiveKit работает как SFU: принимает медиапотоки и пересылает их нужным участникам. Это избавляет проект от необходимости самостоятельно реализовывать ICE, NAT traversal, обработку RTP и адаптацию качества. Интерфейс, авторизация, каналы и правила доступа остаются нашим кодом. FastAPI подходит для прикладного API и WebSocket-событий, но медиапотоки через него не передаются.

## Известный сервер крестиков-ноликов

Сохранённые сведения о существующем VPS:

- Selectel, 1 vCPU, 1 GB RAM, 10 GB SSD;
- Ubuntu 24.04 LTS;
- Python/Flask-приложение за Gunicorn (это действующее приложение крестиков-ноликов);
- Nginx как reverse proxy, systemd для запуска;
- Gunicorn настроен на 1 worker и 2 threads.

Удалённое подключение к VPS в этой рабочей сессии недоступно, поэтому перед деплоем эти параметры нужно подтвердить командами на сервере. Локальный компьютер разработки — отдельная машина под Ubuntu 25.10.

## Решение по размещению

- Домен проекта зарегистрирован: `coherent-web.ru`.
- Основной сайт, API, база и LiveKit будут размещены на зарубежном VPS.
- Существующий российский VPS не используется как входная точка и не требуется для первого запуска Coherent.
- Если нагрузка на медиа окажется высокой, LiveKit можно вынести на второй зарубежный VPS.

Текущие сведения о российском VPS сохранены только как исторический контекст. Перед развёртыванием нужно проверить ресурсы, сеть и firewall нового зарубежного VPS. Актуальная схема — в [инструкции по развёртыванию](deployment.md).

## Оценка ресурсов для 10 участников

Текущий российский VPS **1 vCPU / 1 GB / 10 GB не подходит для надёжного одновременного размещения Coherent и LiveKit**. Для первого контролируемого теста на зарубежном VPS с одной активной демонстрацией экрана и преимущественно аудио разумно начать с 2 vCPU и 4 GB RAM. Если ожидаются камеры у многих участников одновременно — ориентир 4 vCPU и 8 GB RAM, либо отдельный зарубежный VPS под LiveKit.

Это стартовые оценки, а не гарантия вместимости: нагрузка SFU зависит от числа публикуемых дорожек, подписчиков и объёма данных, пересылаемого каждому участнику. Перед постоянным использованием потребуется тест на реальных устройствах и сетях.

Для self-hosted LiveKit нужны домен и TLS. Также потребуется открыть сетевые порты для WebRTC: в стандартной конфигурации это UDP 50000–60000, TCP 7881 и, при включённом TURN, UDP 3478. При настройке UDP mux можно использовать UDP 7882 вместо диапазона. Точный список зависит от конфигурации, NAT и сетевого экрана нового провайдера. Наличие Nginx само по себе эти UDP-порты не проксирует.

Для сайта и выдачи сертификатов также используются TCP 443 и 80. Если потребуется TURN/TLS, его порт и совместное использование TCP 443 с Nginx нужно будет настроить отдельно. Для Coherent FastAPI будет работать через Uvicorn, а Nginx проксирует HTTP и WebSocket. Настройки Gunicorn с двумя потоками относятся только к существующему Flask-приложению крестиков-ноликов.

Перед основной разработкой нужно сделать короткую проверку рисков в целевом Chrome/Chromium на Ubuntu: захват звука выбранной вкладки без повторной передачи голоса звонка, выбор устройств вывода и локальное изменение громкости одного участника. `getDisplayMedia()` работает только в защищённом контексте и набор источников аудио зависит от браузера и ОС; `setSinkId()` для выбора выхода тоже требует HTTPS, разрешения пользователя и поддержки браузера. См. [MDN: Screen Capture API](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Capture_API/Using_Screen_Capture), [MDN: restrictOwnAudio](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/restrictOwnAudio) и [MDN: setSinkId()](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/setSinkId).
