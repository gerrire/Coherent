# Развёртывание Coherent

## Основной вариант

Все основные компоненты размещаются на одном зарубежном VPS:

```text
coherent-web.ru ──HTTPS──► Nginx ──► интерфейс и FastAPI
media.coherent-web.ru ──WSS──► LiveKit на том же VPS
браузер ──WebRTC/UDP или TCP──► LiveKit на том же VPS
FastAPI ──локальная сеть──► PostgreSQL
```

Российский VPS не нужен для основного трафика. Его можно будет использовать позже для вспомогательной задачи, если появится конкретная необходимость. Подключение пользователей и маршрутизация медиапотоков остаются на зарубежном сервере.

## Что требуется перед первым публичным запуском

1. Выбрать зарубежный VPS и подтвердить, что провайдер разрешает нужные входящие UDP-порты и исходящий трафик. Начальная оценка для небольшого закрытого запуска: 2 vCPU / 4 ГБ RAM; при нескольких камерах и демонстрации экрана разумнее 4 vCPU / 8 ГБ RAM. Эти числа нужно подтвердить нагрузкой на реальных устройствах.
2. Создать DNS-записи `A` для `coherent-web.ru` и `media.coherent-web.ru`, направленные на IP зарубежного VPS.
3. Настроить HTTPS для сайта и WSS для LiveKit. FastAPI и PostgreSQL не должны иметь открытых публичных портов. `LIVEKIT_URL` в API должен быть `wss://media.coherent-web.ru`.
4. Открыть веб-порты 80/443 TCP, а для LiveKit — медиапорты согласно его конфигурации. Обычный Nginx обрабатывает HTTPS и WebSocket, но не переносит WebRTC/UDP. LiveKit может использовать диапазон UDP 50000–60000 либо один UDP-порт 7882 при настройке UDP mux; резервный ICE/TCP обычно использует 7881.
5. Сгенерировать отдельные `SECRET_KEY`, `LIVEKIT_API_KEY` и `LIVEKIT_API_SECRET`, задать `APP_ENV=production`, `COOKIE_SECURE=true`, `CORS_ORIGINS=["https://coherent-web.ru"]`. Ключ LiveKit хранится только на сервере API.
6. Настроить резервные копии PostgreSQL и обновление контейнеров. Перед открытым доступом проверить звонок между двумя реальными сетями, включая входящий вызов, камеру и показ экрана.

Локальный Compose в репозитории предназначен для разработки, а профиль `calls` запускает LiveKit в небезопасном dev-режиме. Его нельзя переносить на публичный VPS без новой конфигурации и собственных ключей.

Источники: [LiveKit: порты и firewall](https://docs.livekit.io/transport/self-hosting/ports-firewall/), [LiveKit: развёртывание на VM](https://docs.livekit.io/transport/self-hosting/vm/), [LiveKit: локальный режим](https://docs.livekit.io/transport/self-hosting/local/).
