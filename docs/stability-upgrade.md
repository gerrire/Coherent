# Исправления по аудиту 27 октября 2026

Статус: реализация в ветке `security-stability`, проверки и выкладка ещё не завершены. Документ описывает внесённый код; результаты подтверждения записываются после проверок.

Владелец исключил из этого этапа доставку писем и ограничения одного маломощного VPS. Восстановление забытого пароля через почту, почтовая доставляемость, несколько процессов realtime и увеличение серверных мощностей в этот этап не входят. API ботов остаётся отложенным.

## Защита и переписка

- Каждый запрос резервирования MLS-отправки подписывает доверенное устройство; одноразовые подтверждения не заменяют друг друга между вкладками.
- Попытки входа ограничены по IP и существующему аккаунту; хеширование паролей выполняется вне цикла API. Выход отзывает конкретный токен, открытый WebSocket имеет срок действия.
- Сброс доверия создаёт новые 12 слов и новый архивный корень. Все остальные устройства и сессии теряют доверие. Для них требуется повторное подтверждение. Сохраняются зашифрованные корни старой истории; отозвать уже прочитанные или скопированные данные невозможно.
- Резервный пакет восстановления по-прежнему не содержит закрытых ключей устройств и MLS-ratchet. Старые 12/24-словные пакеты читаются. Новые слова не передаются почте или API.
- Смена корня контакта требует сверки нового кода. Исторические подписи проверяются по корням, подтверждённым новым подписанным списком.
- Добавление/удаление участников группы сопровождается MLS-изменением состава. У новых участников должны быть подготовлены ключи; есть выход из группы и управление составом владельцем.
- Для старой облачной истории показан статус переноса. Перенос собственного сообщения возобновляемый; устройство другого автора должно выполнить свою часть.

## Звонки и клиент

- Ключ медиа выводится из отдельной MLS-группы звонка, а не из секрета API. Группа включает только аккаунты, находящиеся в звонке. Участники синхронизируют ключ при изменении состава.
- LiveKit отправляет подписанные события подключения. Недопущенный участник отключается; периодическая сверка остаётся дополнительным механизмом. Короткий токен сам по себе не считается отзывом доступа на self-hosted LiveKit.
- Сбой одной комнаты не отменяет обработку остальных и не сбрасывает всё время отсутствия.
- Изменение шумоподавления перенастраивает исходный микрофон. Обработка не переключается через выходную синтетическую дорожку.
- Отметки чтения учитывают фокус и прокрутку. Уведомления используют подтверждение доставки вкладке и внутреннюю навигацию без перезагрузки звонка.
- Файлы, не попавшие в очередь отправки, удаляются из локального кеша. Криптооперации ограничены по времени; процесс восстанавливается после аварии.
- Локальное хранилище браузера переходит с JSON-массивов байтов на бинарный формат с чтением старой версии. Ядро кешируется с проверкой ревизии и блокировкой между вкладками. Независимые беседы не удерживают сетевую блокировку друг друга.
- Windows использует короткую блокировку сессии, не удерживая её на время загрузки файла. Оригинальный ключ подписи обновлений необходим для выпуска 0.1.2; новая сборка готовится только Windows runner.

## Серверы и сопровождение

- Добавлены выход, исключение участника, роли участник/модератор, передача владения, переименование и удаление каналов/сервера. Персональные ACL каналов и голосовые комнаты серверов — отдельное расширение.
- Беседы выдаются страницами без потери старых записей. Участники списка загружаются пакетно; realtime обновляет затронутую беседу.
- Админка показывает защищённое хранилище, остаток облачной истории, API p95/ошибки, сеть и состояние резервной копии. Операционная история хранится 7 дней.
- Просроченные протокольные данные освобождают учтённое место; отпечатки использованных одноразовых пакетов сохраняются для защиты от повторного использования.
- Общий лимит вложений остаётся 15 ГиБ, хранение — 3 дня. Логи контейнеров ограничены и ротируются. API работает без root и с файловой системой только для чтения, кроме явно выделенных каталогов.
- CI использует тот же Python и зафиксированные зависимости. VPS получает уже собранные образы с проверкой контрольных сумм. Перед миграцией создаётся копия БД; при неудаче возвращаются предыдущие образы. Автоматического восстановления старой БД с потерей новых данных нет.
- `pull-encrypted-backup.py` обеспечивает внешнее зашифрованное хранение БД и мастер-ключа. Файлы медиа не копируются сверх трёхдневной политики. Наличие скрипта не означает, что внешний таймер уже установлен или проверено восстановление.
