# Coherent

Coherent — приложение для общения с личными и групповыми сообщениями, голосовыми и видеозвонками и демонстрацией экрана. Проект развивается как самостоятельный продукт на Python и FastAPI. Интерфейс использует тёмную палитру с насыщенным фиолетовым акцентом.

## Windows-клиент

Первый публичный выпуск — **Coherent Desktop 0.1.0**. Скачайте `Coherent-setup.exe` в [GitHub Releases](https://github.com/gerrire/Coherent/releases/latest). Следующие исправления получают номера 0.1.1, 0.1.2 и далее.

Клиент на Tauri 2 и Rust использует локальный интерфейс, нативный захват экрана и системного звука, трей, окно входящего звонка и подписанные обновления внутри приложения. Исходники Windows находятся в ветке `codex/desktop-rebuild`. [Сборка и устройство клиента](frontend/src-tauri/README.md), [возможности и ограничения выпуска](docs/releases/desktop-0.1.0.md), [результаты проверок](docs/desktop-stabilization.md).

## Текущий этап

Сейчас готов первый рабочий срез:

- регистрация и вход по имени пользователя и паролю, без обязательной почты;
- вход и выход из аккаунта;
- сохранение сессии в защищённой от JavaScript cookie;
- CSRF-защита изменяющих запросов;
- поиск пользователей по имени;
- отправка, принятие и отмена заявок в друзья;
- личные и групповые текстовые беседы с историей, загрузкой ранних сообщений и доставкой новых сообщений через WebSocket;
- личные и групповые звонки до 10 участников с приглашением, принятием и выходом; голос, камера и показ экрана через LiveKit;
- сетка и фокусный режим звонка, индивидуальная громкость участников, выбор устройств, видеокодека, качества камеры и демонстрации экрана, подавление шума и эха;
- список друзей и адаптивный интерфейс в тёмно-фиолетовой палитре;
- PostgreSQL для разработки и Alembic для миграций.

Начать личную беседу и позвонить можно любому найденному пользователю — добавление в друзья не требуется. Из открытой беседы можно также отправить заявку в друзья. Для группового звонка выбирают минимум двух друзей: создаётся отдельный общий чат, название которого можно менять. В действующий групповой звонок можно пригласить своих друзей, и они станут участниками общего чата. Громкость собеседника регулируется на его плитке. Камера по умолчанию предпочитает H.264 и 1080p; демонстрация экрана — 1080p при 30 кадрах/с с выбором исходного разрешения и режима для текста или движения. Для звонков нужно отдельно запустить LiveKit и задать его настройки. В беседу можно прикрепить до четырёх файлов, перетащив их на вкладку, вставив из буфера обмена через Ctrl+V или выбрав кнопкой. Лимит: 25 МБ на файл и 50 МБ на сообщение. Файлы удаляются с сервера через три дня, текст сообщений сохраняется.

Старые аккаунты продолжают работать: войти в них можно по имени пользователя. В меню профиля доступны настройки аккаунта и смена пароля без ввода старого пароля. После смены пароля другие сеансы завершаются.

Исходные продуктовые решения и условия приёмки сохранены в [спецификации MVP](docs/MVP.md), техническая схема — в [описании архитектуры](docs/architecture.md), а границы модулей для следующих этапов — в [архитектурной карте](docs/architecture-roadmap.md).

| Часть | Технологии |
| --- | --- |
| Backend | Python 3.12+, FastAPI, SQLAlchemy 2, Pydantic |
| База данных | PostgreSQL 17, Alembic |

## Структура проекта

```text
backend/
  alembic/                 Миграции базы данных
  src/coherent_api/
    api/                    HTTP-маршруты и зависимости
    core/                   Настройки и безопасность
    db/                     Базовый класс моделей и подключение к БД
    models/                 Аккаунты, друзья, беседы, сообщения и звонки
    schemas/                Схемы запросов и ответов
    services/               Логика аккаунтов, друзей и переписки
  tests/                    Тесты API
frontend/
  src/
    components/             Авторизация, друзья, беседы и звонки
    lib/                    Клиент API
compose.yaml                PostgreSQL для локальной разработки
docs/                       Спецификация MVP и архитектура
```

## Запуск локально

Нужны Python 3.12 или новее, Node.js 20.19+ и Docker Compose.

### 1. Подготовить окружение и базу данных

Из корневой папки репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e "backend[dev]"
cp .env.example .env
docker compose up -d database
```

В `.env` замени `SECRET_KEY` на случайную строку. Для локальной разработки оставь `APP_ENV=development` и `COOKIE_SECURE=false`.

Для локальной базы Compose использует пользователя `coherent`, пароль `coherent` и порт хоста `5433`, чтобы не мешать другой PostgreSQL на `5432`. Если меняешь порт, обнови `POSTGRES_PORT` и `DATABASE_URL` в `.env`. Если меняешь пароль, обнови его и в `DATABASE_URL` в `.env`, и в настройках базы данных в `compose.yaml`.

### 2. Запустить API

В новом терминале из корня репозитория:

```bash
source .venv/bin/activate
cd backend
alembic upgrade head
uvicorn coherent_api.main:app --app-dir src --reload
```

API будет доступен на `http://127.0.0.1:8000`, интерактивная документация — на `http://127.0.0.1:8000/api/docs`.

Если `alembic upgrade head` сообщает `password authentication failed`, сначала проверь, что `DATABASE_URL` указывает на порт Coherent из `POSTGRES_PORT`. Уже созданный Docker-том также мог сохранить пароль от старой конфигурации. Тогда обнови пароль роли в работающем контейнере, не удаляя данные:

```bash
docker compose exec database psql -U coherent -d coherent -c "ALTER ROLE coherent WITH PASSWORD 'coherent';"
```

После этого повтори `alembic upgrade head`. Если подключение всё ещё не удаётся, проверь опубликованный порт (`docker compose ps`) и `DATABASE_URL` в `.env`.

### 3. Запустить интерфейс

В ещё одном терминале:

```bash
cd frontend
npm install
npm run dev
```

Открой адрес, показанный Vite, обычно `http://localhost:5173`. Vite перенаправляет запросы `/api` на локальный backend.

### 4. Включить локальные звонки

Для разработки на Linux запусти LiveKit отдельным сервисом:

```bash
docker compose --profile calls up -d livekit
```

Раскомментируй три переменные `LIVEKIT_*` в `.env.example` и перенеси их в свой `.env`, затем перезапусти API. Для локального режима LiveKit использует ключ `devkey` и секрет `secret`; в публичном окружении нужны собственные ключи и `wss://`.

В личной беседе появится кнопка «Позвонить». Входящий вызов виден в открытом приложении, после принятия доступны микрофон, камера и демонстрация экрана. Звук выбранной вкладки передаётся, если браузер разрешил его захват. Вызов, на который не ответили за минуту, истекает; активный звонок ограничен четырьмя часами. Пока события звонков, как и сообщений, требуют одного процесса API, а интерфейс дополнительно опрашивает сервер.

## Настройки перед развёртыванием

Перед публичным запуском задай сильный `SECRET_KEY`, включи `APP_ENV=production` и `COOKIE_SECURE=true`, укажи адрес production-интерфейса в `CORS_ORIGINS` и настрой HTTPS. Не добавляй `.env` и реальные пароли в Git.

Основной вариант размещения — один зарубежный VPS для сайта, API, PostgreSQL и LiveKit. Домен сайта и отдельный адрес для LiveKit указывают на него напрямую. Российский VPS для первого запуска не нужен. Подробности — в [схеме развёртывания](docs/deployment.md).

Пока события сообщений рассылаются через память одного процесса API. Для нескольких процессов или серверов потребуется общий канал событий; клиентский опрос раз в 15 секунд служит запасным способом обновления.
